# 离线织造排产台

由原「手工织锦纹样排版台」改造，纯前端、零依赖、离线运行：直接打开 `index.html` 即可，全部数据保存在浏览器 localStorage（键名 `zxWeavingDB_v1`），刷新不丢失。

## 业务流程

1. **绘制草稿**：网格填色、调色线、改行列数都只作用于草稿，不影响已锁定版本和织造单。
2. **锁定纹样版本**：每个版本把「网格行列 + 格点 + 色线库」整体快照锁定，之后不可变；版本列表永久留档。
3. **断线复核**：锁定版本后逐行评估换色密度。
   - 换色率 > 62% 为**高风险行**，> 45% 为中风险提示；
   - 创建织造单前必须完成断线复核：高风险行未全部复核时，新建单只能进入「待复核」，不能开工；
   - 复核记录绑定具体版本，锁定新版本后复核必须重做。
4. **创建织造单**：同一织机同时只能有一张未完工单（待复核 / 已排产 / 织造中均占用织机）。
   - 重复提交（相同请求号）或并发提交返回 **409**，且**不落库**；
   - 界面提交时会自检并发（同请求连发两次），演示一次成功一次 409。
5. **开工与改版冻结**：
   - 已排产 → 开工（织造中）→ 完工；
   - 开工后再修改纹样 / 色线 / 行列数并锁定新版本，织造中的旧单**立即冻结留档**（保留旧快照、冻结时间与原因，不可复活），织机随即释放；
   - 对新版本补做断线复核后按新纹样重排新单（复核补齐时待复核单自动转已排产）。

## 模块划分

| 文件 | 业务模块 | 职责 |
| --- | --- | --- |
| `js/status.js` | 状态计算 | 织造单状态机、织机占用、列表派生视图（纯计算） |
| `js/review.js` | 断线复核 | 版本快照的逐行风险评估与复核记录（纯计算 + 判定） |
| `js/store.js` | 持久化 | 离线读写；单次同步事务，冲突时整次不写库 |
| `js/api.js` | 服务编排 | 三模块编排，在途写锁 + 事务内二次冲突校验，返回 HTTP 式 `{code, body}` |
| `js/app.js` | 界面 | 渲染与交互，不含业务规则 |

列表、风险提示、织机占用全部由 `status.js` / `review.js` 根据持久化数据现算，因此刷新前后结果一致。
