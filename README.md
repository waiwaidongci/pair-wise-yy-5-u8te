# 离线织造排产台

由原「手工织锦纹样排版台」改造而成，直接打开 `index.html` 即可离线使用（数据存 localStorage，无需服务端）。

## 业务规则

- **纹样版本锁定**：点击「锁定为新版本」后，系统按当前网格（行列数 + 逐格色线）和色线库生成不可变快照（含指纹），版本一经锁定不再修改。
- **建单先复核**：创建织造单前必须完成断线复核。复核逐行统计换色次数，换色超过列数 62% 的行判为高风险行，必须逐条签认；未完成复核时建单返回 422 且不落库。
- **高风险行只能待复核**：建单时存在任一高风险行，织造单初始状态只能为「待复核」；高风险行全部签认处置后才能放行至「待开工」。无高风险版本复核后直接「待开工」。
- **一织机一未完工单**：同一织机只允许一张未完工单（待复核 / 待开工 / 织造中），重复提交（相同幂等键）或并发提交（提交锁被占用）返回 409，且不落库。已冻结 / 已完工单不占用织机。
- **开工改纹样即冻结**：织造中修改纹样、色线或行列数，旧单立即冻结并留档（旧快照随单可查）；补做新版本断线复核后，可用同机台按新纹样重新建单重排。

## 模块拆分（`js/` 目录）

| 文件 | 模块 | 职责 |
| --- | --- | --- |
| `review.js` | 断线复核 `BreakReview` | 纹样指纹、逐行换色统计、高风险判定、复核完成判定 |
| `status.js` | 状态计算 `OrderStatus` | 状态集合、流转规则、占用判定、允许动作 |
| `store.js` | 持久化 `OfflineStore` | localStorage 落库、REST 风格异步请求（201/200/422/409）、幂等键、并发锁、冻结留档 |
| `app.js` | UI 编排 | 绘制、复核面板、建单、工单列表；不含业务口径 |

列表徽标、风险提示与复核面板都只从 `BreakReview` / `OrderStatus` 取结果，因此刷新后（以及跨标签）显示完全一致。

## 演练

1. 绘制并「锁定为新版本」，在右侧逐条签认高风险行后保存复核。
2. 选择机台创建织造单；机台被占用时建单返回 409。
3. 点页首「演练：重复提交(409)」可用相同幂等键再次提交，观察 409 且无重复落库。
4. 对织造中点「开工」后，在画布上改任何颜色或行列数，旧单立即变为「已冻结」；锁定新版本并补做复核后，点旧单「按新纹样重排」重新建单。
